# Техническое задание (ТЗ) — Мобильное приложение «My Collection» (Версия 1.0 / MVP)

---

## 1. Общие сведения и цель проекта

* **Название проекта:** «My Collection»
* **Назначение:** Мобильное приложение для персонального учёта коллекционных предметов. Помогает коллекционеру вести каталог своих вещей, быстро проверять наличие предмета в коллекции и привязывать фотографии к записям.
* **Целевая аудитория:** Пользователи смартфонов, ведущие учёт личной коллекции (монеты, марки, комиксы, фигурки, винил, книги и т.д.), которые сейчас используют стандартные заметки и галерею телефона.
* **Формат реализации:** Кроссплатформенное мобильное приложение (iOS / Android) с возможностью запуска и тестирования в обычном веб-браузере.

---

## 2. Стек технологий и архитектура

* **Фронтенд-фреймворк:** React (TypeScript или JavaScript, функциональные компоненты, хуки).
* **Сборщик:** Vite (быстрая локальная сборка и запуск dev-сервера).
* **Мобильная оболочка:** Capacitor (упаковка веб-приложения в нативное мобильное приложение).
* **Стилизация и иконки:** Tailwind CSS (или модульный CSS), библиотека иконок Lucide React.
* **Локальное хранилище данных:** `localStorage` (браузерное key-value хранилище) или `@capacitor/preferences` — данные сохраняются на устройстве и не теряются при перезапуске приложения.
* **Работа с изображениями (MVP):** Локальное чтение изображений через стандартный HTML File Input (`accept="image/*"`) или плагин `@capacitor/camera` с сохранением в base64 / DataURL в локальном хранилище.

---

## 3. Границы проекта (Scope) первой версии

### 3.1. Что входит в версию 1.0 (MVP)
1. **Каталог предметов:** список всех добавленных предметов в виде карточек/плитки с фото и названием.
2. **Поиск:** мгновенная фильтрация списка по названию предмета.
3. **Карточка предмета:** детальный просмотр названия, описания и фотографии в полном размере.
4. **Добавление предмета:** форма ввода названия, описания и выбора фотографии.
5. **Редактирование предмета:** изменение существующих данных или удаление фотографии.
6. **Удаление предмета:** безвозвратное удаление с диалогом подтверждения.
7. **Локальное сохранение данных:** сохранение всех записей на устройстве пользователя.

### 3.2. Что НЕ входит в версию 1.0 (Out of Scope)
* Регистрация, авторизация и личные кабинеты (работа строго офлайн, без бэкенда).
* Облачная синхронизация между устройствами.
* Социальные функции (публикация, комментарии, лайки).
* Категории, теги и множественные папки (пока только общий каталог для простоты v1).
* Распознавание предметов по фото через ИИ.
* Корзина и восстановление удалённых записей.
* Экспорт/импорт базы (перенесено на следующие версии).

## 4. Структура данных (Модель Item)

Каждый предмет в коллекции описывается следующей структурой:

| Поле | Тип данных | Обязательное | Описание |
| :--- | :--- | :---: | :--- |
| `id` | `string` | Да | Уникальный идентификатор (генерируется автоматически, например `crypto.randomUUID()` или таймстемп). |
| `title` | `string` | Да | Название предмета (не пустое, пробелы по краям обрезаются). |
| `description` | `string` | Нет | Подробное описание или заметка о предмете (многострочный текст). |
| `image` | `string \| null` | Нет | Изображение предмета (Base64 DataURL). |
| `createdAt` | `number` | Да | Время добавления предмета (таймстемп в миллисекундах для сортировки). |
| `updatedAt` | `number` | Да | Время последнего редактирования. |

## 5. Экраны и сценарии взаимодействия (Screen Flow)

Приложение состоит из 3 основных экранных состояний:
1. **Экран каталога (Главный экран)**
2. **Экран / Модальное окно просмотра карточки предмета**
3. **Экран / Модальное окно формы (Создание / Редактирование)**

```
Каталог (Главный экран)
├── Поиск по названию
├── Кнопка «Добавить» (+) ────> Форма добавления (пустая)
│                                 ├── «Сохранить» ──> Карточка нового предмета
│                                 └── «Отмена» ────> Каталог (с проверкой изменений)
│
└── Нажатие на карточку ──────> Карточка предмета
                                 ├── Кнопка «Назад» ──────> Каталог
                                 ├── Кнопка «Изменить» ───> Форма редактирования
                                 │                            ├── «Сохранить» ──> Обновлённая карточка
                                 │                            └── «Отмена» ────> Карточка предмета
                                 └── Кнопка «Удалить» ────> Диалог подтверждения
                                                              ├── «Отмена» ──> Остаться в карточке
                                                              └── «Удалить» ─> Каталог (без предмета)
```

---

## 6. Детальные требования к экранам и логике

### 6.1. Экран «Каталог» (Главный)
* **Шапка:** Заголовок «Моя коллекция», счетчик предметов (например, *«Всего: 12»*).
* **Поле поиска:**
  * Текстовое поле ввода с иконкой лупы и кнопкой быстрой очистки (крестик).
  * Поиск фильтрует список "на лету" (при каждом введённом символе).
  * Фильтрация нечувствительна к регистру (*«монета»* находит *«Монета»*).
  * Поиск по частичному совпадению подстроки.
  * Если поле пустое — отображаются все предметы.
  * Если ничего не найдено — отображается плашка: *«Ничего не найдено по запросу "[запрос]"»*.
* **Список предметов:**
  * Отображение в виде адаптивной сетки (2 колонки на смартфонах) или списка.
  * Элемент списка содержит: миниатюру фото (или заглушку-плейсхолдер, если фото нет), название предмета.
  * Сортировка по умолчанию: новые добавленные предметы сверху (`createdAt DESC`).
* **Пустое состояние (Empty State):**
  * Если в коллекции нет ни одного предмета, показывается дружелюбное сообщение: *«Ваша коллекция пока пуста. Нажмите кнопку "+", чтобы добавить первый предмет»*.
* **Кнопка добавления:**
  * Заметная плавающая кнопка (Floating Action Button) или кнопка в шапке с иконкой `+` («Добавить»).
  * По клику открывает чистую форму добавления предмета.

---

### 6.2. Экран «Форма добавления / редактирования»
* **Поля формы:**
  1. **Фотография:** область для предварительного просмотра.
     * Если фото нет: кнопка «Выбрать фото».
     * Если фото выбрано: предпросмотр изображения и кнопка «Удалить фото» / «Заменить фото».
  2. **Название (обязательное):**
     * Однострочное текстовое поле с плейсхолдером *«Введите название предмета»*.
     * Валидация: поле не может быть пустым или состоять только из пробелов.
  3. **Описание (необязательное):**
     * Многострочное текстовое поле с плейсхолдером *«Дополнительные детали, состояние, год и т.д.»*.
* **Управление формой (Кнопки):**
  * **«Отмена» / стрелка назад:**
    * Если пользователь не вносил изменений — форма сразу закрывается.
    * Если пользователь что-то ввёл или изменил — показывается диалог: *«Несохранённые изменения. Закрыть форму без сохранения?»* с вариантами *«Остаться»* и *«Выйти»*.
  * **«Сохранить»:**
    * Если название не заполнено — блокируется или подсвечивается ошибкой: *«Пожалуйста, укажите название предмета»*. Данные из остальных полей не сбрасываются.
    * При успешном сохранении нового предмета — переход сразу в карточку этого предмета.
    * При успешном сохранении изменений существующего предмета — возвращение в карточку с обновленными данными.

---

### 6.3. Экран «Карточка предмета»
* **Содержимое:**
  * Кнопка «Назад» в верхнем левом углу (возвращает в Каталог).
  * Полноразмерное изображение (или стильная заглушка с иконкой коллекции, если фото не загружено).
  * Название предмета (крупный заголовок).
  * Дата добавления предмета.
  * Текст описания (если описания нет — не отображается или пишется *«Описание не указано»*).
* **Действия:**
  * Кнопка **«Редактировать»** (карандаш) — открывает форму редактирования с подставленными текущими данными.
  * Кнопка **«Удалить»** (корзина) — вызывает модальное окно подтверждения удаления.

---

### 6.4. Логика удаления предмета
* При нажатии на кнопку удаления появляется диалоговое окно (модалка):
  * Заголовок: *«Удалить предмет?»*
  * Текст: *«Вы уверены, что хотите удалить «[Название предмета]»? Это действие нельзя отменить.»*
  * Кнопки: **«Отмена»** (серая/нейтральная) и **«Удалить»** (акцентная красная).
* При выборе «Отмена» диалог закрывается, пользователь остаётся в карточке.
* При подтверждении удаления:
  * Запись удаляется из хранилища.
  * Экран карточки закрывается, происходит переход в Каталог.

---

## 7. Требования к UI / UX и мобильной адаптации

1. **Мобильная ориентация:** Интерфейс разрабатывается в первую очередь под мобильные устройства (Mobile First).
2. **Учет Safe Area:** Отступы сверху и снизу (челка/вырез камеры и нижняя полоса жестов iPhone/Android) должны корректно обрабатываться (`env(safe-area-inset-top)`, `env(safe-area-inset-bottom)`).
3. **Touch-friendly:** Все интерактивные элементы (кнопки, поля ввода, карточки) должны иметь достаточный размер для нажатия пальцем (минимум 44×44 px).
4. **Быстрый отклик:** Отсутствие задержек при нажатии (активные состояния `:active`, плавная анимация переходов).

---

## 8. Критерии приёмки (Done Definition)

Версия 1.0 считается полностью готовой, если:
1. Пользователь может добавить новый предмет с названием, описанием и фотографией.
2. Невозможно сохранить предмет без названия или с названием из одних пробелов.
3. Добавленный предмет сразу отображается в каталоге.
4. Поиск мгновенно фильтрует список предметов по части названия без учета регистра.
5. При нажатии на предмет открывается подробная карточка.
6. Данные предмета можно отредактировать (включая удаление/замену фото).
7. Предмет можно удалить после обязательного подтверждения в диалоговом окне.
8. **Главный технический критерий:** при полной перезагрузке страницы в браузере или перезапуске мобильного приложения все созданные записи и фото сохраняются без потерь.
